# nuxi init のテンプレート 5 種の違い

`npx nuxi init` の対話で最初に聞かれる「テンプレート選択」の詳細解説。`docs/setup/frontend.md` の対話項目表の深掘り。

## テンプレートとは

テンプレートは「**どんな部品が最初から組み込まれた状態でプロジェクトが生まれるか**」の選択です。家を建てるときの「更地から建てる / 家具付き物件を買う / 工場(家を作る側)を建てる」の違いに近く、**あとから部品を足すことはできる**ので、迷ったら小さく始めるのが定石です。

## 5 種の比較

| テンプレート | 一言でいうと | 最初から入っているもの | 向いている用途 |
|---|---|---|---|
| **minimal** | 更地 + 骨組みだけの家 | Nuxt 本体のみ(`app.vue`、`nuxt.config.ts` などの最小ファイル) | 普通の Web アプリ全般。**このリポジトリはこれ** |
| **content** | ブログ向け家具付き物件 | Nuxt Content モジュール(Markdown ファイルをページに変換する仕組み) | ブログ、ドキュメントサイト、お知らせページなどの「記事」中心のサイト |
| **ui** | デザイナー内装済み物件 | Nuxt UI モジュール(ボタンやフォームなどの完成済みコンポーネント集。Tailwind CSS ベース) | 画面の見た目を早く整えたいアプリ。UI 部品を自作したくない場合 |
| **module** | 家ではなく「家の部品工場」 | モジュール開発用の雛形(`src/module.ts`、動作確認用の playground など) | **アプリではない**。Nuxt の拡張ライブラリ(モジュール)を作って npm で配布する人向け |
| **v5-nightly** | 建築中の実験住宅 | Nuxt 5 の**開発中ビルド**(nightly = 毎晩最新のコードから作られる未安定版) | 次期バージョンの新機能を試したい人。壊れることが前提なので実プロジェクトには使わない |

## それぞれの補足

### minimal — 迷ったらこれ

「最小(minimal)」という名前のとおり、Nuxt が動くために必要なファイルしか入っていません。中身がほぼ空なので、プロジェクトの構造を自分で理解しながら育てられるのが学習用途にも合っています。content や ui に入っているモジュールは、**あとから `npm install` + 設定追加でいつでも足せる**ので、minimal を選んで損をすることはありません。

### content — 「記事を書くサイト」専用の追加装備

Nuxt Content というモジュールが入っています。これは `content/` フォルダに置いた Markdown ファイルを自動でページに変換してくれる仕組みで、ブログやドキュメントサイトを Markdown だけで量産できます。逆に言うと、DB と API でデータをやり取りする今回のようなアプリには出番がありません。

### ui — 見た目の部品が最初から揃っている

Nuxt UI というコンポーネントライブラリ(ボタン、モーダル、テーブルなどの完成品部品集)と、そのベースの Tailwind CSS(HTML に短いクラス名を書いてスタイルを当てる CSS フレームワーク)が入っています。便利ですが「Nuxt UI 流の書き方」を最初から覚えることになるので、まず Nuxt 自体を学びたい段階では情報量が多すぎます。

### module — アプリを作る人には関係ない

これだけ毛色が違い、**Nuxt アプリではなく「Nuxt を拡張する部品(モジュール)」を開発するため**の雛形です。生成されるのは `src/module.ts`(モジュール本体)と playground(動作確認用のミニアプリ)で、`npm run dev` で起動するのも playground の方です。Nuxt Content や Nuxt UI のようなライブラリを自作して配布したくなったときに使います。

### v5-nightly — 未来の Nuxt の試食版

nightly は「毎晩、その日の最新の開発コードから自動ビルドされる版」のことです。正式リリース前の Nuxt 5 を試せますが、日によって動いたり壊れたりします。バグ報告や新機能の先行検証が目的の選択肢で、消えて困るコードを書く場所ではありません。

## このリポジトリで minimal を選ぶ理由

- 用途は「REST API(`/api`)+ 画面」のシンプルなアプリで、Markdown 記事(content)も完成品 UI 部品(ui)も必須ではない
- 学習リポジトリなので、余計な部品が入っていない状態から構造を理解しながら育てたい
- 必要になったモジュールは後から追加できる(選択は取り返しがつく)

## 落とし穴

- **テンプレート選択は「初期装備」の違いでしかない。** minimal で始めても、`npm install @nuxt/ui` などで後から ui 相当にできる。逆に content で始めて Nuxt Content を使わないと、使わない部品を抱え続けることになる
- **module だけは別物。** 「UI モジュールが欲しいから module かな」と名前で選ぶと、アプリではないものが生成されて面食らう
- **v5-nightly を「最新版だから良さそう」で選ばない。** 最新 = 安定ではない。安定版の最新は minimal が生成する Nuxt 4

## 用語集

- **テンプレート** — プロジェクト生成時の初期構成の選択肢。初期装備の違い
- **モジュール(Nuxt モジュール)** — Nuxt に機能を追加する拡張ライブラリ。`nuxt.config.ts` に登録して使う
- **Nuxt Content** — Markdown をページに変換する公式モジュール
- **Nuxt UI** — 完成済み UI コンポーネント集の公式モジュール
- **Tailwind CSS** — HTML のクラス名でスタイルを当てる CSS フレームワーク。Nuxt UI の土台
- **nightly** — 毎晩最新の開発コードから自動生成される未安定ビルド
- **playground** — モジュール開発時に動作確認するためのミニアプリ
