# Java の型明示と型推論(var) — 変数宣言でどこまで型を書くか

「Java は TypeScript のように型を省略できないのか? 変数宣言のたびに必ず型を書かないといけないのか?」という疑問への答えをまとめた学習メモ。結論を先に言うと、**Java も型推論の仕組み(`var`)を持っているが、使える場所がローカル変数に限られる**。TypeScript ほど自由には省けない、という「程度の違い」の話。

## 前提 — Java も TypeScript も「静的型付け」

まず押さえておきたいのは、Java と TypeScript は**どちらも静的型付け言語**(型をコンパイル時にチェックする言語)だということ。「型があるか無いか」の違いではない。違うのは **型推論(型を書かなくてもコンパイラが右辺などから型を察してくれる仕組み)をどこまで許すか**という一点。

| | 型推論の効く範囲 | 型注釈の位置づけ |
|---|---|---|
| **TypeScript** | ほぼどこでも(変数・戻り値・引数のデフォルトなど) | 任意。安全性や意図の明示のために「書きたければ書く」 |
| **Java** | ローカル変数の `var` だけ | 多くの場所で必須。省けるのは限定的 |

TypeScript は「基本は推論に任せ、必要な所だけ注釈」。Java は「基本は明示、省けるのはローカル変数だけ」。真逆に近い。

## var — ローカル変数だけ型を省ける(Java 10 以降)

Java 10(2018年)で **`var`** が入り、**メソッドの中のローカル変数**に限って型を省略できるようになった。右辺から型が推論される。

```java
// 型を明示する書き方
List<Post> fetched = postRepository.findTimeline(cursor, categoryId, PageRequest.of(0, limit + 1));

// var を使う書き方(右辺の戻り値から List<Post> と推論される)
var fetched = postRepository.findTimeline(cursor, categoryId, PageRequest.of(0, limit + 1));
```

`var` は「型が無くなった」のではなく「**コンパイラが右辺から型を確定させて、その型に固定する**」もの。上の `fetched` は `List<Post>` 型に確定していて、あとから別の型を入れることはできない。ここが「型のない言語の変数」とは根本的に違う。

## var が使えない場所 — ここは型の明示が必須

`var` の適用範囲はかなり狭い。次の場所では **`var` は使えず、型を書くことが必須**。

| 場所 | 例 | var 可否 |
|---|---|---|
| ローカル変数(初期値あり) | `var user = ...;` | ✅ 使える |
| **フィールド**(クラスの変数) | `private final PostRepository repo;` | ❌ 型必須 |
| **メソッドの引数** | `getTimeline(Long cursor, ...)` | ❌ 型必須 |
| **メソッドの戻り値の型** | `public TimelineResponse getTimeline(...)` | ❌ 型必須 |
| 初期値を与えない変数 | `var x;`(右辺が無い) | ❌ 不可(推論材料が無い) |

理由はどれも「**推論する材料が無い、または他者との約束事だから**」。フィールド・引数・戻り値は「このクラスの外と交わす契約」にあたる部分で、ここを推論任せにすると呼ぶ側が型を読み取れなくなる。だから **関数の入口(引数)・出口(戻り値)とフィールドは必ず型を書く**、というのが Java の姿。TypeScript が引数や戻り値も推論・省略しやすいのとは対照的。

## このプロジェクトの方針 — ローカル変数も型を明示する

このリポジトリの backend コードは、`var` を使わず **ローカル変数でも型を明示するスタイル**で統一されている。

```java
// PostService.getTimeline より(型を明示)
List<Post> fetched = postRepository.findTimeline(...);
boolean hasNext = fetched.size() > limit;
List<Post> page = hasNext ? fetched.subList(0, limit) : fetched;
```

`var` も文法上は使えるが、あえて明示している。どちらが絶対的に正しいというものではなく(`var` にも「右辺で型が自明なときは冗長さが減る」という利点がある)、**プロジェクト内で書き方を揃えることが優先**、という判断。既存コードに合わせるのが原則。

## つまずきポイント

- **「Java は型推論が無い」は誤解。** 昔(Java 9 以前)は無かったが、今は `var` がある。ただし TypeScript 感覚で「どこでも省ける」と思うと、フィールドや引数で書けずに詰まる
- **`var` は「なんでも入る箱」ではない。** `var x = 10;` の `x` は `int` に確定する。あとから `x = "abc";` はできない。動的型付け言語の変数とは別物
- **`var` に `null` だけを入れることはできない。** `var x = null;` は型を推論できずコンパイルエラー。何の `null` か分からないため
- **戻り値の型は書く場所であって省く場所ではない。** メソッドシグネチャ(名前・引数・戻り値の型)は呼ぶ側との契約なので、ここは常に明示

## 用語集

- **静的型付け** — 型をコンパイル時に確定・検査する方式。Java も TypeScript もこれに属する
- **型推論** — 型注釈を書かなくても、コンパイラが右辺などから型を自動で決める仕組み
- **var** — Java 10 で導入された、ローカル変数の型を省略するキーワード。型が消えるのではなく右辺から確定する
- **ローカル変数** — メソッドの中で宣言する変数。`var` が使えるのはここだけ
- **フィールド** — クラスが持つ変数(PHP でいうプロパティ)。型の明示が必須
- **メソッドシグネチャ** — メソッドの名前・引数・戻り値の型のまとまり。呼ぶ側との契約なので型を明示する
