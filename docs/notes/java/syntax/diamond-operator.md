# ダイヤモンド演算子(`<>`) — 型引数の書き直しを省く記法

`new LinkedHashMap<>()` の `<>` は何なのか、をまとめた学習メモ。結論を先に言うと:

- **`<>` は「型引数は左辺と同じなので書かない」という指示。** 型が消えるのではなく、コンパイラが埋める
- **`<>` と「何も書かない」は別物。** `new LinkedHashMap()` はエラーにならないが、型チェックが無効になる危険な書き方(raw type)
- **そもそも `<>` という記号が必要なのは Java の歴史的事情。** 「無印」がすでに別の意味に取られていたので、新しい記号を足すしかなかった
- **TypeScript には相当する記法が無い。** 書かなければ推論されるので、わざわざ記号を置く必要がない
- **PHP には言語機能としてのジェネリクスが無い。** `array<string, string>` は静的解析ツール向けの注釈で、PHP 本体は見ていない

## 0. 前提 — ジェネリクスとは

`<>` の話に入る前に、`List<Post>` の `<Post>` の部分を押さえておく。これを **ジェネリクス**(総称型)と呼ぶ。

**「入れ物の型」だけでなく「中に入る型」まで指定する仕組み**のこと。`List` が入れ物、`<Post>` が中身。この `<Post>` の位置に書くものを **型引数** と言う。

なぜ必要か。ジェネリクスが無かった頃(Java 5 以前)はこうだった。

```java
// 昔の書き方 — 中身の型を指定できない
List list = new ArrayList();
list.add(post);
list.add("うっかり文字列");            // ← 通ってしまう

Post p = (Post) list.get(1);          // ← 取り出すたびキャストが必要。
                                      //   しかもここで実行時エラーになる
```

中身が何か分からないので、取り出すたびに `(Post)` と書いて型を戻す(キャストする)必要があり、間違っていても**動かしてみるまで気付けなかった**。

```java
// 今の書き方 — 中身の型を宣言する
List<Post> list = new ArrayList<>();
list.add(post);
list.add("うっかり文字列");            // ← コンパイルエラー。入れる時点で止まる

Post p = list.get(0);                 // ← キャスト不要。最初から Post として出てくる
```

**入口(入れるとき)と出口(取り出すとき)の両方をコンパイラが見張ってくれる。** これがジェネリクスの効能。

## 1. `<>` が省いているもの

ジェネリクスは Java 5(2004年)で入ったが、当初は**同じ型引数を2回書く**必要があった。

```java
// Java 6 以前 — 左辺と右辺で <String, String> を2度書く
Map<String, String> fieldErrors = new LinkedHashMap<String, String>();
```

右辺の `<String, String>` は左辺を見れば分かりきっている。この重複を省くために **Java 7(2011年)** で入ったのが `<>`。**山括弧2つの形がダイヤモンドに見える**ことから、ダイヤモンド演算子と呼ばれる。

```java
// Java 7 以降 — GlobalExceptionHandler の実際のコード
Map<String, String> fieldErrors = new LinkedHashMap<>();
```

「左辺に書いてある型引数を、ここにも当てはめて」という意味。結果として作られるのは `LinkedHashMap<String, String>` で、Java 6 以前の書き方と**完全に同じもの**。短く書けるだけで、動きは1ミリも変わらない。

**省略されるのは型引数だけで、クラス名は省略されない**点に注意。上の例は左辺が `Map`、右辺が `LinkedHashMap` と別のクラスだが、これは問題ない。`Map` が「仕様(インターフェース)」で `LinkedHashMap` が「実際の入れ物(実装)」という関係になっている。

## 2. `<>` と「何も書かない」は別物 ← いちばん重要

`<>` を書き忘れて `new LinkedHashMap()` としても、**コンパイルは通ってしまう**。しかし意味がまったく違う。

```java
Map<String, String> a = new LinkedHashMap<String, String>();  // ① 明示
Map<String, String> b = new LinkedHashMap<>();                // ② ダイヤモンド
Map<String, String> c = new LinkedHashMap();                  // ③ 無印 = raw type
```

| 書き方 | 呼び名 | 型チェック | 評価 |
|---|---|---|---|
| ① `<String, String>` | 型引数の明示 | ✅ 効く | 動くが冗長 |
| ② `<>` | **ダイヤモンド演算子** | ✅ 効く | **これを使う** |
| ③ 何も書かない | **raw type(生の型)** | ❌ **無効になる** | 使ってはいけない |

③は「型引数を忘れた」ではなく「**ジェネリクスを使わない、Java 5 以前のモード**」という明示的な意味を持ってしまう。コンパイラは `unchecked` 警告を出すだけで止めてくれず、以降その入れ物に対する型の守りが外れる。§0 で見た「うっかり文字列が入る」世界に逆戻りする。

**なぜこんな紛らわしい仕様なのか。** Java 5 でジェネリクスを導入したとき、世の中には `new ArrayList()` と書かれた既存コードが山ほどあった。それらを動かし続けるために、「無印 = 昔の意味(raw type)」を変えるわけにいかなかった。そこで **「推論してほしい」を表す新しい記号として `<>` を足す** しかなかった。`<>` という記号が存在すること自体が、後方互換性のための産物だということ。

## 3. `<>` が効く場所 — 「左辺」だけではない

`<>` は正確には「左辺を見る」のではなく「**その式に期待されている型(ターゲット型)から推論する**」。だから代入以外でも効く。

```java
// ① 変数宣言 — 左辺の型から
Map<String, String> fieldErrors = new LinkedHashMap<>();

// ② メソッドの引数 — 引数として宣言された型から
someMethod(new ArrayList<>());        // 引数が List<Post> なら ArrayList<Post> になる

// ③ return 文 — メソッドの戻り値の型から
public List<Post> empty() {
    return new ArrayList<>();         // 戻り値の型が List<Post> なので ArrayList<Post>
}
```

逆に言うと、**推論の材料になる「期待されている型」が存在しない場所では `<>` は機能しない**。次章がその典型例。

## 4. `var` と組み合わせるときの落とし穴

このプロジェクトは型を明示する方針だが(→ [type-declaration-and-var.md](./type-declaration-and-var.md))、`var` を使う場面では注意が要る。

```java
// 型を明示 → <> が効く
List<String> a = new ArrayList<>();   // ArrayList<String>

// var → 推論の材料が無い
var b = new ArrayList<>();            // ArrayList<Object> になってしまう!
b.add(123);                           // 通ってしまう(String を入れる箱のつもりだったのに)

// var を使うなら、右辺に型引数を書く
var c = new ArrayList<String>();      // ArrayList<String>
```

`var` は「右辺から左辺の型を決める」仕組み、`<>` は「左辺から右辺の型引数を決める」仕組み。**両方を同時に使うと、互いに相手を見ようとして誰も答えを持っていない状態になる。** このときコンパイラはエラーにせず、すべての型の親である `Object` を当てはめて黙って通してしまう。

「`var` と `<>` は同時に使わない」と覚えておけばよい。どちらか一方に型を書く。

## 5. 他の言語との違い

### TypeScript — 相当する記法は「無い」。書かなくていいから

TypeScript にもジェネリクスがあり、書き方は Java によく似ている。

```typescript
// 型引数を明示
const a = new Map<string, string>();

// 左辺に型注釈があれば、右辺は空でよい
const b: Map<string, string> = new Map();   // ← <> のような記号は不要
```

つまり **TypeScript では「何も書かない」がそのまま「推論して」の意味**になる。Java で言う③(raw type)にあたる書き方が存在せず、その位置が空いているので、`<>` という追加記号を発明する必要がなかった。

これは §2 で見たとおり、**TypeScript は最初から型があった言語で、守るべき「ジェネリクス以前のコード」が無かった**から。Java が抱えている後方互換性の負債が、そのまま記法の差になっている。

なお TypeScript は引数からも型引数を推論する。

```typescript
const c = new Map([["body", "本文を入力してください"]]);  // Map<string, string> と推論される
```

### PHP — 言語機能としてのジェネリクスが無い

PHP には**そもそもジェネリクスが無い**。配列にも `Collection` にも「中身の型」を書く文法が用意されていない。

```php
// 中身が何かを言語に伝える手段が無い
$fieldErrors = [];
$fieldErrors['body'] = '本文を入力してください';
$fieldErrors['x'] = 123;   // 何を入れても止められない
```

代わりに使われるのが **PHPDoc の型注釈**。

```php
/** @var array<string, string> $fieldErrors */
$fieldErrors = [];
```

`array<string, string>` という書き方は Java の `Map<String, String>` に似ているが、性質がまったく違う。**これはコメントであり、PHP 本体は一切見ていない。** PHPStan や Psalm といった静的解析ツールを別途走らせたときにだけチェックされ、実行時には何の効力もない。

| | Java | TypeScript | PHP |
|---|---|---|---|
| ジェネリクス | ✅ 言語機能 | ✅ 言語機能 | ❌ 無い(PHPDoc + 外部ツール) |
| 型引数の省略 | **`<>` が必要** | 書かなければ推論 | — |
| 型チェックのタイミング | コンパイル時 | コンパイル時(実行時には消える) | 静的解析ツールを走らせたときだけ |
| 型情報は実行時に残るか | ❌ 消える(型消去) | ❌ 消える | — |

Java と TypeScript が共通しているのは、**型引数の情報が実行時には消える**こと。だから Java では `List<String>.class` と書けず(→ [class-literal.md](./class-literal.md))、TypeScript でも実行時に `T` が何だったかを知る手段がない。

## つまずきポイント

- **`<>` を書き忘れても動いてしまう。** `new ArrayList()` はコンパイルエラーにならず、代わりに型チェックが静かに無効化される。警告(`unchecked`)が出ていたら見逃さない
- **`<>` は左辺のクラス名まで省略しているわけではない。** 省略しているのは型引数だけ。`Map<String, String> m = new LinkedHashMap<>();` のように左右のクラスが違ってよい
- **`var` と `<>` の併用は事故になる。** エラーにならず `Object` が入るので気付きにくい。どちらか一方に型を書く
- **型引数にプリミティブ型は書けない。** `List<int>` は不可で `List<Integer>` と書く。ジェネリクスはオブジェクト型しか受け取れない
- **実行時に型引数は分からない。** `List<String>` と `List<Post>` は実行時には区別できない(型消去)

## 用語集

- **ジェネリクス(総称型)** — `List<Post>` の `<Post>` のように「中に入る型」を指定して型安全にする仕組み
- **型引数** — `<>` の中に書く具体的な型。`Map<String, String>` なら `String` と `String` の2つ
- **ダイヤモンド演算子** — `<>`。型引数を「ターゲット型と同じ」として省略する記法。Java 7 で導入
- **ターゲット型** — その式に期待されている型。変数宣言の左辺、メソッドの引数の型、メソッドの戻り値の型のこと。`<>` はここから推論する
- **raw type(生の型)** — `new ArrayList()` のように型引数をまったく書かない形。ジェネリクス導入前との互換のために残されているが、型チェックが効かなくなる
- **型消去** — ジェネリクスの型引数がコンパイル後に消える Java の仕様。実行時には `List<String>` も `List<Post>` もただの `List`
- **キャスト** — `(Post) obj` のように型を強制的に変換する記法。ジェネリクスはこれを不要にするために入った
