# commit-message

ステージ済み（`git add` 済み）の差分を読み、コミットメッセージを生成して**出力するだけ**のスキル。
**コミットは絶対にしない。** ユーザーが出力を `/copy` でコピーして自分でコミットに使う。

## 入力

`/commit-message [任意のヒント]`

- 引数は任意の自由記述のヒント（例: `/commit-message リファクタリング中心で`）。
- ヒントがあれば type・要約に反映する。なければ差分だけから推定する。

## 手順

1. `git diff --cached --stat` と `git diff --cached` を実行し、ステージ済みの差分を読む。
2. **ステージが空なら**（差分が何もない）、「まだ何も git add されていません」と伝えて**停止する**。
   - 勝手に `git add` してはいけない。
3. `git log --oneline -20` を読み、そのリポジトリの既存コミットスタイルを確認する。
4. 既存スタイルに追従してメッセージを作る。
   - 判別できなければ **Conventional Commits**（`type: 要約`）をデフォルトにする。
   - type は差分内容から選ぶ: `feat / fix / docs / refactor / test / chore / style / perf`。
   - 本文は**日本語**で書く。
5. メッセージ構造:
   - 1行目: 要約（50字目安）
   - 2行目: 空行
   - 3行目以降: 本文（なぜ・何を変えたか。箇条書き可。不要なら省略）

## 出力

- 解説（type 選定理由など）は応答の**上**に数行だけ。
- **コミットメッセージ本体は、応答の最後に単独のコードブロックで置く。**
  `/copy` でそのままコピーできるようにするため、本体の後ろには何も書かない。
- **Co-Authored-By 行などは付けない**（ユーザー自身のコミットになるため）。

出力例:

```
docs: JPA エンティティの no-arg コンストラクタについてのメモを追加

- Hibernate がリフレクションでインスタンス化する際に必要な理由を記載
```

## やってはいけないこと

- `git commit` / `git add` / `git push` などの git 操作を実行しない。
- プロジェクト固有の情報をスキル内にハードコードしない（他プロジェクトへコピーして使えるようにする）。
